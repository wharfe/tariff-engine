# 迷った時に Jev に聞く（選んで使う機能）

**要は**: 既定の `classify()` は今のまま（AI なし・ネット不要・同期）。使う人が選んだ時だけ使える非同期の
`classifyWithDecider()` を足し、ルールが迷った時に判断モデル（既定は Jev）へ聞く。製品の約束は
「既定では動かす時に AI を使わない」に言い直す。

上位: 2026-10-02 の A 案（対応表）は 144 問で効果なし（`2026-10-02-jev-lookup-table.md` の結果）。
前提（実測・調整用の 144 問で）: ルールは 97% の問題で要確認になる。Jev の項の確信度が 0.7 以上なら Jev、
それ未満ならルールを採ると 88%（Jev だけ 86%、ルールだけ 59%）。

## 使い方
```ts
import { classifyWithDecider, loadTree } from "tariff-engine";
import { jevDecider } from "tariff-engine/jev";
loadTree();
const r = await classifyWithDecider({ description: "toothpaste, 100g" }, { decider: jevDecider({ apiKey }) });
```
- 判断モデルは差し替えられる形（`Decider` = 状態・指示・選択肢・取り消し信号を渡すと、選択と確率と確信度を返す関数）。Jev 用は別の入口
  `tariff-engine/jev` に置き、本体は今と同じく外部依存なし。通信は Node 標準の `fetch` だけ。
- 鍵は呼ぶ側が渡す（本体は環境変数もファイルも読まない）。

## 動き
1. まずルールで分類（今の `classify()`）。要確認でなければ、そこで返す（通信なし）。
2. それ以外は判断モデルに 3 段（章 97 択 → 項 → 号）で聞く。選択肢 1 つの段は聞かない。
3. 項の確信度が 0.7 以上なら判断モデルの答えを先頭にし、2 位以降にルールの候補。
   理由欄は木の経路＋「Decider: 章 0.xx / 項 0.xx / 号 0.xx」。要確認は判断モデルの確信度で決める。
4. 0.7 未満、または通信の失敗・時間切れ（全体で 1 つの締め切り、既定 5 秒）なら、ルールの結果を返し要確認にする。
   失敗は結果の `decider` 欄に理由を載せる（例外にしない）。時間切れでは通信そのものを取り消す（裏で再試行・課金が続かない）。
5. 判断モデルの返り値は全部確かめる: 選んだキーが選択肢にあること、確信度が 0〜1 の数であること。満たさなければ失敗扱い。
6. 要確認は、章・項・号のどれかの確信度が 0.8 未満なら true（要確認なし＝ 6 桁まで信じてよい答え）。
7. 失敗の理由に鍵を含めない（状態コードだけ。応答本文は載せない）。

## 測り方（合格の線）
**根っこ**: 判定に使う問題は、ルールの調整にも判断モデルの線の調整にも使っていないものでなければならない。
手元の 50 問はルールの調整に使った（コミット 244ed4e）、144 問は判断モデルの線の調整に使った、難問 20 問は 50 問の一部。
どれも判定には使えないので、**新しい判定用の問題を外から持ってくる**。

- **判定用**: 米国税関の公開裁定（CROSS、`rulings.cbp.gov`）の **2026-07-01 以降の全件**（検索語で選ばない。
  `term=classification` を新しい順に送り、7/1 より古くなったら止める。実測で約 410 件）。商品の説明は裁定の件名、
  正解は人が決めた関税番号の上 6 桁（HS 2022 と同じ）。
  - 条件（どちらのモデルの答えも見る前にここで固定）: 関税番号が 1 つ、件名が「classification of 〈品〉 from 〈国〉」の形、
    6 桁が木にある。件名が同じものは 1 件にまとめ、同じ件名で正解が違うものは除く。
  - 「件名だけでは決まらない」印: ® ™ や引用符を含む（製品名つき）、または正解が 61・62 章なのに件名に
    knit / woven / crochet が無い。印つきも判定に含め、印なしだけの値も別に報告する。
  - `tests/fixtures/cross-2026h2.json` に裁定番号つきで固定し、以後は調整に使わない。判定は 1 回だけ。
  - 最近の裁定に限るのは、この裁定そのものを判断モデルが学習していない見込みが高いため（同じ品の古い裁定は覚えているかもしれない）。
- 合格の線（全部満たす）:
  1. 項の 1 位が **ルールだけより 10 ポイント以上高い**。
  2. 同じ問題どうしの食い違いで見て、差が偶然でない（McNemar の正確検定・**両側**で p < 0.05）。
  3. 判断モデルを採って**要確認なしで返した答え**が、判定用の **25% 以上**あり、その **6 桁の正解率の Wilson 95% 下限が 0.85 以上**。
     届かなければ 0.8 をいじらずに報告。
  - 判断モデルが時間切れ・失敗で使えなかった件数も数え、**5% を超えたら判定を無効**にして止める（通信の不調と弱さを混ぜない）。
- 参考（合否に使わない）: 50 問（ルール調整に使用済みと注記）、144 問（線の調整に使用済み）での値。
- 試験では通信しない（決まった答えを返す偽の判断モデルで動きを確かめる）。実際の Jev を呼ぶ判定は別の手順で 1 回。
- 既定の `classify()` の結果・速さ・依存は変わらない（既存の試験がそのまま通る）。
- 線（0.7 / 0.8）をいじったら、それ以降その判定用の問題は調整用の扱いにし、報告にそう書く。
